# 第2步：小幅主动试探与可观测性诊断

2026-10-05。继续原四步规划的第2步；这些诊断不是新增完整跨越结果。

## 实际做了什么

- 水平 `horizontal_encoder_live_whole_coil` 的0/16/32/40秒、竖直 `vertical_encoder_live_whole_coil` 的2/10/22/34秒恢复诊断初态。有/无管配对仅在独立负对照副本中关闭目标管碰撞，没有改变有管组摩擦、力矩或重力。
- 每次1.2秒：0.2秒保持，0.8秒同时施加三组互不重叠的0.6°扰动，再0.2秒返回。三组为前部后缘的一对正交关节与前部收拢，频率互异。前部范围来自先前估计的双轴归属，未使用真实接触编号。
- 角度和下发目标生成三组谐波响应，最小幅值为额外机械约束特征。真实接触/自由基座位姿列为 `evaluation_only`，不进入特征。
- 水平8个有/无管样本定阈值0.4865247591，竖直8个冻结复核均匹配。只区分本组管道存在性，不证明力封闭、承载裕量或方向正确，不能直接据此释放尾部。其他障碍也可造成低响应。
- 有管组峰值关节速度7.9–31.6°/s，头部净位移1.7–8.2 mm。无管对照存在快速滑落，不计为平顺运动。

## 文件与复现

- `summary.json`、`classification.json`、`horizontal_rule.json`：特征、运动影响和冻结规则。
- `feedback_takeover_active_probe.py`：生成数据时源码。`protocol.json` 的竖直多频时刻已按实际记录校正，未改变命令或轨迹。
- `geometry_window*.json`：同窗口单帧/多帧CAD拟合，增大数值差分步长未稳定改善。
- `wrench_direction.json`：假设尾部静止、未知重力方向、只有法向反作用的方向扫描；未改善，不采用。
- 相邻 `active_takeover/`、`active_takeover_distinct/`：较早单方向试探及失败结果。
- `../feedback_takeover/pitch_axis_probe.json`、`fixed_radius_probe.json`：已有轨迹的几何先验诊断，没有物理闭环更新。

## 后续坐标与距离诊断

`../feedback_takeover/contact_odometry_probe.json` 与 `normal_odometry_probe.json` 分别假设候选接触点完全不滑、仅保持法向接触。每种均比较独立积分和CAD校正。独立积分漂移明显；加CAD后水平最大轴误差仍为52.14°/21.51°，竖直83.50°/86.58°，未采用。候选接触不足时退回原局部配准，次数记录在文件内，没有用真实接触补足。

`../feedback_takeover/proximity_oracle_audit.json` 使用真实几何作**诊断评分**，隔离距离查询本身的问题，绝不回送控制器。水平/竖直CAD近接＋负载判据精确率83.97%/83.55%、召回率95.21%/95.64%；实际原管接触已消失而仍预测存在的帧数分别1/0（每0.2秒抽样，前100秒）。因此有必要继续解决几何跟踪，不能把所有误判归为距离接口损坏。

两组已知信息闭环检查了支撑交接：`horizontal_observation_reserve_oracle` 在前部持续一圈包绕、前缀10节、接触角覆盖180°达到0.6秒前保留后部8关节；完整跨越但模块峰值0.620m/s超限。`horizontal_observation_reserve_phase` 再将尾部释放额度绑定前部实际rolling增量，200秒未完整跨越、峰值0.571m/s。两组都未采用；控制分段仍保留尾部不等于实际原管支撑还在。源码、轨迹和命令归档于相邻 `feedback_takeover/archives/`。

## 动态响应的几何辨识与位姿跟踪

`validation/feedback_takeover_dynamic_fit.py` 用0.8秒关节角/指令历史拟合虚拟两管几何、未知重力方向，剩余0.4秒检查预测。几何先验仍为相交直角、相近半径；使用准确的名义机器人和摩擦模型。真实管轴、重力方向、自由位姿/速度与接触不进入拟合，只用于结束后的评分。

- 水平首窗口目标方向误差0.0101°、直线偏移0.035mm；训练/留出关节预测RMS为0.00115°/0.00070°。这只是一个短窗口，不能据此宣布持续跟踪或实机可行。
- 竖直多初值拟合为1.026°/8.379mm、留出RMS为0.0626°；加入未知初始速度、缩小差分步长并用中心差分后为0.952°/7.581mm、留出0.0507°。未知重力方向仍偏23.45°，结果存在局部最优/辨识不足风险。
- 虚拟模型必须重新编译以重建静态碰撞树。首版仅改编译后几何导致零接触，其 `dynamic_gravity_probe_invalid_no_contacts.json` 是**无效实现诊断**，不能当作信息不足的证据。修正后原机器人质量、执行器和物理参数一致。
- `dynamic_model_oracle_audit.json` 仅用真实初态/几何检查建模误差，短窗口预测RMS约0.00066°/0.00068°；它没有给估计器提供初始化。未建模T支路在这两个短窗口没有接触，见 `dynamic_probe_unmodelled_branch_check.json`。
- 只把实测关节角覆写进内部动力学模型会发散（`dynamic_tracking_*_conditioned.json`），未用于运动控制。模型内部发散/自动重置之后的数值不具有位姿估计意义。
- 早期误差状态滤波只接收编码角与命令。水平前20秒最大轴误差0.025°、偏移0.054mm；但将1ms局部线性化重复近似20ms会在水平24.7秒、竖直66.78秒发散。完整20ms映射求导仍在水平24.68秒发散，排除仅由这一近似造成。加入编码角差分速度推迟失效；限制局部更新后持续到120秒，但协方差仍溢出。这些失败均保留，没有用私有模型自动重置后的状态声称成功。

### 后续跟踪结果与闭环接入边界

滤波器限制内部位姿修正的线性近似范围，并对局部高斯协方差设置有限尺度，防止弱可观方向导致数值溢出；这些都是估计器的假设，不修改物理位姿或力。水平140秒不再发散，轴误差中位数0.003°、95%分位0.723°、最大3.211°。竖直按六种水平/竖直重力假设的响应误差选出方向后，170秒数值上持续运行，但约62–64秒轴误差达到61.8°，不能采用为可靠跟踪。

事后诊断发现第三管臂的接触未建模。新增L形、原管继续延伸、目标管反向延伸三个虚拟模型；各模型从同一上一时刻估计状态预测，连续三帧关节预测RMS改善40%才切换。实际管轴、接触和场景标签不选择模型。水平/竖直均由数据选择原管延伸模型。再次回放：

| 记录 | 时长 | 轴误差中位 / 95% / 最大 | 直线偏移中位 / 95% / 最大 | 模型支撑精确率 / 召回率 |
| --- | --- | --- | --- | --- |
| 水平 | 140s | 0.006° / 1.006° / 2.365° | 0.053 / 5.584 / 18.379mm | 98.37% / 95.21% |
| 竖直 | 2–149s | 0.042° / 1.649° / 16.027° | 0.336 / 12.375 / 79.680mm | 97.51% / 94.17% |

竖直截止149秒是因为原轨迹149.96秒驶出有限长管道，而当前虚拟模型尚不估计管端；保留170秒失败数据，不把管端后的偏差删除后冒充全场景通过。两组所采样帧中，原管真实接触全部消失后仍推断原管接触的帧数均为0；不代表力封闭或无漏报。竖直47.6秒还有16°短时误差，必须在实际闭环中验证影响。单次估计墙钟中位约13ms、95%分位约22ms，不能宣称稳定满足20ms硬实时。

`feedback_takeover_response_calibration.py` 把统一标定整理为不接受场景名称、真值轴、真实位姿/速度/接触的API。它从当前几何候选和角度/指令记录先求自由重力，再比较六个重力方向假设，不读取历史拟合答案。复核水平/竖直留出关节RMS为0.00066°/0.03728°。每次标定耗时数分钟；MuJoCo同步实验在计算期间不推进仿真时间，实机部署的实时性尚未解决。

新增 `--dynamic-observer` 在同一轮隔离EXE实验中执行1.2秒、60条探测命令，随后标定，再把私有模型估计的几何和接触供给原径向承接控制器。探测和rolling都保留原物理参数及真实初态，所有真实轴/接触/自由位姿只供评分。首轮水平 `horizontal_response_dynamics` 正在运行；离线改善尚未被称为闭环通过。

上述均为记录回放/诊断，未增加新的物理闭环成功，尚未接入自然搭管与完整自主流程。实际机器人没有被修正位姿；仅内部预测模型进行状态校正。求解耗时高于控制周期，实时性和模型误差稳健性尚未验收。
