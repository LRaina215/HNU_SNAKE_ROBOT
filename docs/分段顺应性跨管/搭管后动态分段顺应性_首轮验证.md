# 搭管后动态分段顺应性：首轮验证

日期：2026-10-04。状态：**独立实验实现与数据审计完成，运动验收未通过。**

## 本轮问题和边界

从用户已经搭上目标管的状态出发，检验动态分段能否支持进一步rolling转移。最终目标为完整跨越，本轮只验收短程持续转移。

用户逐项确认：已知两根真实管轴、人工初始分段、根据仿真位置/接触迁移边界、公共rolling相位及初始相位偏置，不插入独立伸头/重缠动作。水平T用于开发，冻结后竖直向下T独立复核。三组为原自动单轴、原管真实单轴、真实双轴动态分段。仅允许调整分段/连接相关参数；共同顺应增益、滚动步长、重力、摩擦和执行器参数保持不变。

两个起点分别为用户保存的水平step92、竖直step95；均为20关节、R=81.5 mm、P=220 mm、K=(0.01,0.02)、重力开启、force开启。用户推进方向Ctrl+H，对应每步phase减0.15；每步推进0.2秒物理时间。模型、积分状态和控制器快照已归档到实验目录的`inputs/`，原用户存档未改动。

## 实现

- `snake_control/segmented_pole_backbone.py`：独立几何和控制组件。复用原A–D截面构造、按模块增益和Yamada交替关节积分。初始边界为头起第6个连杆边界附近，过渡长度候选为4、6、8节。
- 目标管与原管方向之间构造五次平滑轴方向场。先建立连续切向，再计算包含轴转动贡献的两个弯曲分量及坐标架转动，统一转换到Bishop标架。轴转动项同时参与目标曲线与关节积分，避免仅拼接两段常螺距曲率/挠率却遗漏转弯。
- 在局部坐标架中，`T=R(s)[cos(alpha)cos(theta), cos(alpha)sin(theta), sin(alpha)]`。`b1=T'·N`、`b2=T'·(T×N)`、`omega=N'·(T×N)`，由积分omega将弯曲量转入共同Bishop标架，再施加公共rolling相位。
- 切换采用一次初始相位对齐和公共相位下转动的弯曲补偿场，补偿在6步内平滑消退。零步目标与原ctrl一致；**这不保证后续反馈更新都没有大跳变**。4节候选及竖直复核后期观察到了较大的目标变化，见限制。
- 边界用模块中心到两根轴的几何归属代价选出有序切分点，需邻近目标管接触证据连续3步确认，每步最多迁移0.25节，可正反迁移。转移成功依据独立几何判据，不读取控制器的边界标签。
- `validation/segmented_pole_experiment.py`：批处理独立入口，恢复完整存档，经隔离EXE完成Python→EXE→MuJoCo目标转发，100 Hz保存真实物理轨迹。诊断在MjData副本执行，不改变主积分器热启动状态。
- `validation/SegmentedAxisReplay.cs`：直接调用现有EXE程序集中的原轴估计器，用存档的最后有效轴播种其历史。原会话的隐藏估计历史没有完整存档，新EXE直接启动会丢失回退轴；该适配避免把这一恢复缺口误计为原方法的运动失败。估计器以每控制步一次更新，不能声称与用户原GUI异步会话逐帧完全相同。
- 新几何方法的初始切换处理用于真实单轴和双轴组。原组保留存档控制器相位偏移，按原算法继续。因此三组也包含“改表示后的切换”差异，不能将所有差异只归因于分段。

原MuJoCo入口、原顺应控制器、实机入口、可视化源码和物理模型均未修改。新入口用于本轮批处理验证，尚未接入原窗口热键。

## 验收条件与预声明

同时要求：头部沿目标管轴净推进≥64.5 mm；至少两个初始原管/过渡区模块实际转入目标管区域；运动中没有整体脱落；结束后固定目标、重力开启继续3秒，仍维持双管接触及支撑。

在有效对照前固定了以下操作化定义，保存在`plan.json`：

- 每组最多80步。整体脱落判为地面接触或全部管道接触连续消失0.2秒；暂失某一根管的接触不直接判为整体脱落。
- 可转移模块为初始人工前缀之外（模块索引≥6）且初始不在目标区域者。头部前缀中的几何分类空洞不会被重复计为新转移。
- 目标区域：模块中心到目标轴比到原轴至少近10 mm；越过交点沿目标方向超过管半径；距目标轴小于管半径＋29 mm壳半径＋15 mm。连续3个控制步满足才计入运动门槛。此为进入区域，不等于完成重包绕。
- 接触法向力门槛0.1 N。3秒保持中两管持续有接触、无地面接触；头部轴向最大回退≤10 mm、根部相对保持起点最大位移≤20 mm。这是有限时长支撑代理指标，不是静力学稳定性证明。
- 成功候选取首个通过者；都失败则按双管有接触时的最大头部位移选一个进入独立复核，并明确仍为失败候选。按此预设规则选择4节，未因6/8节局部转移较好而事后改选。

先期试跑暴露并修复两项评分/停止问题：头部前缀的分类空洞计为新增模块；暂时失去一管接触误判为整体脱落。`segmented_w4`、`v1_*`、`v2_*`保留为探索/截断数据，**不进入正式结果**。正式数据为水平`final_*`、竖直三个目录。冻结文件生成在竖直复核前，验证入口检查源码、计划、候选结果哈希；没有根据竖直结果调参。

下表位移为结束rolling时相对存档的头部轴向净位移，包含切换段，不能单独视为rolling有效推进距离。“新增模块”为结束rolling时持续满足区域条件的数量。达到运动子门槛后转入3秒保持；未达到则运行到80步。

|---|---:|---:|---:|---:|---:|---|
| 水平/原自动单轴 | 33 | 166.7 | 2 | 14.1 | 49.7 | 未通过 |
| 水平/真实单轴 | 28 | 65.1 | 2 | 0.0 | 74.6 | 未通过 |

水平6/8节候选确实出现进一步身体转移，但结束时的形状和接触不能稳定保持。竖直冻结组虽有头部向下位移，未达到新增两模块的门槛，不能称为过弯成功。原方法也能产生很大的头部位移，说明单独比较头部位移不足以评价跨越。

回放和曲线见实验目录每组的`replay.mp4`、`initial.png`、`final.png`，及场景级`comparison.png`。曲线包含切换和保持时段，各组结束时刻不同，不用于同一时刻的直接性能排名。

## 已完成的验证

- 两轴相同：新Bishop积分与原解析积分最大差约3.1e-8 rad。
- 用原轴重算A–D截面：目标角差约3.6e-15 rad。
- 零步切换：目标差约5.6e-17 rad；独立高斯积分与命令积分最大差约1.05e-6 rad。
- 世界切向差分验证轴变化贡献；重建标架正交误差约6.6e-9；边界延迟确认、限速及接触证据检查通过。
- 八组有效试验均独立核验：完整初态一致、命令逐项经EXE实际转发、100 Hz FK重建、管道/模块接触归属、几何区域分类、反馈姿态与物理姿态对应。反馈与FK位置最大差约2.2e-12 mm。
- 每组保留源码快照、哈希、控制目标、反馈几何、模型与积分状态、实际轨迹。代码测试通过不等于运动门槛通过。

## 限制与下一步建议

1. 目前仅有两个用户选定起点，每场景一份；没有成功率或泛化能力结论，也未证明单轴估计是原方法失效的唯一原因。
2. 该实现保留公共相位、设计螺距角和原截面顺应规则。过渡坐标架变化被正确计入，但没有进一步优化过渡曲线的空间贴管程度、局部支撑余量或受力分配。已知轴方向并不自动保证重建曲线的轴位置都与管道中心线重合。
3. 起始目标连续并不等于持续运动稳定。水平4节组后期最大单步目标变化约178.9°，6/8节组约28.4°/28.3°；竖直冻结组后期也出现大变化，截面绕向有两次翻转。沿用原仿真关节限幅策略，未新增实机30°拒绝门槛或改步长；这些问题必须在更进一步应用前解决。本轮无实机输出。
4. 约束较少的头部形变、解旋和竖直下滑都能带来正的头部位移。本轮失败候选的峰值选型规则较弱，独立复核不成功，不据此宣称分段优于原方法。
5. 建议下一轮先做固定相位的切换/保持诊断，分清重新表达形状后的支撑损失与rolling推进导致的损失；优先检查过渡区空间贴合、持续反馈下坐标架/绕向连续性。是否进一步放开局部相位协调，需依据诊断重新定方案。本轮没有继续扩大调参或放开已确认约束。

## 复现

在仓库根目录、用户`mujoco`环境（MuJoCo **3.2.7**）运行。需要现有`visualizer/windows_app/bin/SnakeRobotVisualizer.exe`和Windows .NET Framework C#编译器；实验自行开启隔离、隐藏的EXE，不要求用户保持原MuJoCo窗口。

```powershell
python validation/segmented_pole_checks.py
python validation/segmented_pole_experiment.py --method segmented --transition-links 6 --output validation/results/segmented-local-repeat
python validation/segmented_pole_review.py experiments/segmented_pole_20261004/horizontal/final_segmented_w6 --render
```

输出目录必须是新目录，不覆盖已有实验。其他组使用`--method original`或`--method source_axis`。默认输入归档的水平状态。独立竖直复核入口为`validation/segmented_pole_verify.py`，已完成的数据目录存在时会拒绝重复覆盖；源码或计划变化后不应沿用旧冻结文件。

连续曲线回放的刚体放置用于展示同一弯曲场；`last_command_curve.json`含切换补偿，关节限幅后的实际离散形状以轨迹FK为准。`controls.json`中的`curve_phase0_mm`仅为相位零的几何诊断，不是当前相位的实际机器人姿态。
