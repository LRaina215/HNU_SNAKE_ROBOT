# 搭管状态保存与分段对照

2026-10-04。当前已完成原MuJoCo入口的状态保存/恢复，分段顺应控制尚未接入。

## 手动采集

先启动可视化EXE，在原 `mujoco` 环境、`codes` 目录运行：

```powershell
python Adaptive_Pole_Climbing_Mujoco.py --scene pipe_tee_vertical_down --joints 20
```

这个场景的默认值是 **R=81.5 mm、P=220 mm、K=(0.01, 0.02)，重力开启**。沿用昨天的单步操作，保持顺应性开启。

1. 前部刚搭上目标管、后部还没有明显松开时，等终端显示本步完成，停止继续按运动键。
2. 点击MuJoCo窗口，按 **Ctrl+B**；也可以在启动程序的终端输入 `save` 回车。
3. 看到 `CHECKPOINT 已保存并暂停：...` 即已保存。将这行路径发回聊天，便于读取同一份数据；截图可辅助说明姿态。
4. 首份存档保持 **force关闭**。若继续运动需要force，先保存上述状态，再输入 `force`；如需记录进一步包绕或松散的状态，再次Ctrl+B。每次生成新目录，自动记录force状态，不覆盖前一份。

保存时不会推进物理时间，也不会改动当前控制目标。若当前一步尚未完成或正等待EXE转发，会拒绝保存；等本步完成后重按。无需通过Ctrl+R/U重新形成姿态。暂停本身不证明身体有稳定支撑，后续会单独推进物理时间检验。

## 存档位置与内容

默认保存在仓库 `validation/results/manual-captures/时间_场景_step步数/`，终端输出绝对路径。目录包含：

- `model.mjb`：当前编译后的模型，包括实际重力、摩擦和网格等。
- `state.npz`：MuJoCo积分状态，包括位置、速度、执行目标、求解器热启动量；另存角度/速度/目标数组便于查看。
- `checkpoint.json`：R/P、增益、滚动相位、步数、force、原顺应控制器目标骨架和相位偏移、采集时的可视化几何、版本与文件校验值。

这不是仅保存关节角或截图。存档位于被Git忽略的实验结果目录，提交代码不会自动上传这些数据；需要转移机器时复制整个存档目录。

## 恢复

关闭当前MuJoCo进程，保留可视化EXE，在 `codes` 目录运行（替换目录路径）：

```powershell
python Adaptive_Pole_Climbing_Mujoco.py --restore "D:\...\validation\results\manual-captures\某次保存目录"
```

无需重新指定场景或关节数。使用保存时相同的MuJoCo版本；3.2.7与3.3.0均已测试，但不跨版本加载同一份二进制模型。

恢复后保持暂停，保留相位和force，等待转发端及新鲜几何反馈就绪后直接单步。**不要先按Ctrl+U或Ctrl+R**，它们会重新应用名义螺旋或重置实验。旧网络命令和旧时间戳不会被重放；新的EXE会话重新生成几何反馈，顺应控制器保留保存的相位偏移。

保存的几何是诊断快照，不会覆盖EXE当前的轴/曲线设置。恢复时保持EXE设置一致。已验证的是物理状态恢复、相同目标下的物理延续和控制器参数保持；跨EXE会话的轴拟合及异步几何反馈尚不保证整条顺应闭环逐位相同，后续对照需核对恢复后的几何。
