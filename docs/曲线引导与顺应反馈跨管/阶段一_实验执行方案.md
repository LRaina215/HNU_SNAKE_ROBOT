# 曲线引导与顺应反馈跨管：阶段一实验执行方案

日期：2026-10-06。状态：**本轮 MuJoCo 候选验证已收尾，累计 11 次动力学记录。稳定保持、实际移送和中段暂停/恢复已有证据，但两模块稳定交接与末端保持未通过；阶段成功目标尚未达成。**

本文件保留原始研究任务及验收目标。本轮最终审阅和已执行的授权范围见[阶段一：MuJoCo 连续执行补充](阶段一_仿真连续执行补充.md)，具体记录见[最终执行报告](../../experiments/curve_guided_transfer_20261006/stage_continuation_20261006/phase_report.md)。用户于 2026-10-06 授权的有限续行已推进至当前候选停止，不再逐项等待下一条 prompt，也不继续追加调参。实机由用户另行安排，不得据此恢复已经终止的三段渐进接管方案，或自动扩展到整身跨越、多管型、强化学习。

**历史规划入口：**以下 P0–P4 和原始修订额度记录最初安排，不能要求后续会话从零重做，也不能自动重启已停止候选。五段身体曲线候选已完成本轮保持、路径衔接和有限主动移送验证；仍未解决的是目标侧连续承接与末端稳定，当前结论以上述最终审阅为准。

“尾部不失控掉落”是约束，“完整曲线引导主动身体移送”是待设计的运动方式，两者不能混为一谈。曲线不会提供物理支撑；允许受控暂停、改形或退回。本任务不预设机器人必然能够不停顿地跨管。

## 1. 任务、假设与结论边界

**核心任务：在现有 20 关节机器人前部已搭上目标管的条件下，判断完整曲线所定义的身体移送，结合持续顺应调整，能否产生可重复的实机局部转移；再判断一种新增反馈调整是否改善了实际遇到的问题。**

本轮需要回答三个问题：

| 编号 | 待回答的问题 | 能支持回答的证据 |
| --- | --- | --- |
| Q1 | 身体是否能够按明确的运动要求，主动通过接头并接续转移后续单元？ | 可辨认身体单元的实际迁移、停送时的保持、重复实机记录；不能用参考曲线进度代替 |
| Q2 | 一种基于实际反馈的调整，是否优于不使用该调整的合理对照？ | 同一运动主干、可比初态和运行限制下的成对比较；同时排除“只是换了更好的固定参数”的解释 |
| Q3 | 仿真能预测哪些现象，哪些必须依赖实机判断？ | 同控制计算、对应初态和动作下的形状、进展、滑动及执行响应比较 |

这是可行性与机制筛查，不是统计成功率评估。正面结果最多支持“在所记录条件下，局部主动转移及某一种反馈调整获得初步实机证据”。它不证明自然搭管、整身通过、未知管道识别、多管型统一或论文创新性已经成立。

### 已知依据与尚未证实的内容

- **已记录的事实：**旧方案最后六个开发初态中，3/6 满足全部门槛、5/6 完成跨越功能；这些不是独立抽样得到的成功率。旧方案已终止，不能把其中的单例成功作为新方案通过的证据。依据见[终止结论](../分段顺应性跨管/顺应性跨管_当前实现终止结论.md)。
- **已记录的事实：**已有实机直管、顺应运动和部分变径记录；本任务未取得“实机自然搭管后能够可靠连续跨管”的证据。以[实机日志](../实验记录/实机调试实验日志.md)为基础，执行前核对是否有新增记录。
- **合理推测：**明确身体沿完整曲线移送的运动关系，可能比继续叠加准入、释放条件更容易定位失败原因。这不是已经验证的优越性结论。
- **待验证假设：**当前身体长度、关节能力和接触条件允许至少一段局部转移；已有反馈能够支持至少一种有效调整。两项都允许被本轮否定或保留为未知。

## 2. 固定范围与进入条件

### 2.1 场景和初态

1. 只选一个与现有实物对应的 **90° 急转接头**，优先水平布置。方向、尺寸和选定通路允许作为已知输入。
2. 先确认实物是两管 L 形接头，还是 T 形接头中的一次转向。仿真必须保留对应几何。额外支管参与接触时记录其作用，不能把 T 形结果写成 L 形结果。
3. 不使用平滑圆弧弯管代替急弯。现有 `pipe_bend90`、`pipe_bend90_tight` 属于连续弯；急弯场景应核对 `pipe_elbow90_horizontal` 或与实物对应的 T 形场景。以[场景说明](../仿真场景/实验室急弯与T型场景.md)及实物测量为准。
4. 显式设置 20 关节。仓库存在 26 关节仿真默认配置，不能沿用后声称与实机一致。
5. 从已搭管初态开始，允许人工摆放或采用已有姿态。记录前后包绕方向、各区域占用的身体单元、接头位置、线缆走向及关节姿态。计分时撤去人工托举、牵引；保护装置不得承载机器人。
6. 初态须能在通电控制下短时保持。若连这一点都不能实现，先报告初态不可用；不把随后摆落解释为跨越动作。

初态重复性采用可复现的身体标记、管道标记和关节角范围描述，不要求人工每次摆出数学上完全相同的姿态。允许误差必须在比较前确定，不能看完结果再筛掉失败初态。

### 2.2 实机进入条件

执行会话先核实实机档案、关节方向与零位、有效角度及速度限制、现行供电和负载停止条件、通信失效处理、操作者可用性。优先复用已确认的实机流程；**仿真力矩限幅、历史电流峰值、旧实验速度门槛不等于经过确认的实机运行限值。**

保持 EXE 对串口的唯一控制权；一个周期只下发一组完整目标角。不得同时运行旧步态和新步态争夺目标写入。真实命令入口、反馈字段与采样时序以当前接口为准，历史串口号不能作为自动连接依据。

如果没有实机访问、操作人员、可核实的运行限值或基本反馈，本轮在相应节点交付 `READY_FOR_REAL` 或缺项说明。不得用增加仿真数量代替实机证据。

## 3. 控制方案与证据隔离

### 3.1 只实现一个候选运动主干

先对照文献和实际尺寸，选定一条完整的“原管包绕—过渡—目标管包绕”曲线。优先审查 2023 年硕士论文第 4.4 节中“螺旋—圆弧—直线—圆弧—螺旋”的管外跨越构造；可以因当前机器人约束修改，但必须说明修改依据。本轮不并行开发多个步态家族。

在开始动力学试验前，完成以下设计输出：

- 给出曲线参数、连接处位置与切向、标架转角、前后螺旋旋向、各段长度及实际身体占用区间。先核对长度与关节限制，不要求前后机械地各绕满一圈。
- 分别定义身体沿曲线的移送坐标、滚动相位和顺应状态；推导它们如何共同生成同一组关节目标。必须能追踪“同一个身体单元怎样从原管侧进入目标管侧”。
- 说明过渡段相对接头的位置和方向如何维持，以及滚动和移送如何配合。不能让两侧独立滚动后假定连接部分自然不动。也不强制所有阶段保持非零滚动：若该构造搭管后依赖切向移送，应按推导实现并说明。
- 说明顺应修正作用于哪一层、如何限幅、如何保留持续的移送要求。不能不断将受阻的当前形状设为新目标，直至前进要求消失。
- 从实际初态平滑接入参考曲线，避免突然改写目标角。直线段不能直接使用在零曲率处奇异的标架计算。
- 写清当接头退化为直管时，曲线、参数和顺应计算与现有 2023 基线的对应关系。本轮只做结构说明和必要的几何核对，不由此声称直管至 U 型管已经统一验证。

复用已有几何、关节角生成和通信模块时，核对其适用条件。旧实现并非“从未使用曲线”；新候选必须说明完整移送关系的实质变化，不能只将旧成形、接管变量改名。

### 3.2 三种运行条件

| 条件 | 定义 | 用途 |
| --- | --- | --- |
| C0：保持 | 同样的初态和局部顺应控制，不给身体移送及对应滚动指令 | 测量无主动移送要求时的漂移、滑动及保持能力 |
| B：基础移送 | 完整曲线移送 + 持续局部顺应；移送及相位安排预先固定，不加入本轮新增协调反馈 | 验证运动主干；提供对照 |
| F：反馈移送 | 保留 B 的运动主干和局部顺应，只增加一种针对实机问题的反馈调整 | 检验新增反馈的贡献 |

这里比较的是“新增协调反馈”的作用。B 本身已有局部顺应反馈，不能把 B/F 比较写成“所有反馈与完全无反馈”的对比。

若 F 的主要作用是遇阻减速，比较对象应为开发记录支持的固定保守速度版本 `B_cmp`；若主要是改变一个形状参数，应考虑合理的固定参数对照。`B_cmp` 在正式比较前一次性确定，不故意选弱对照，也不要求无界搜索最优常数。若本轮无法排除固定参数优化的解释，只能报告组合方案改善，不能宣称自适应决策本身优越。

### 3.3 哪些信息可以进入控制器

- 固定的管道方向、尺寸、任务通路和初态登记属于本阶段明确允许的先验，记录来源和误差。
- 在线反馈优先使用实际可用的关节角、负载相关信号、命令及响应历史。必须列出真实字段；总电源电流不能改称逐关节力矩。
- 仿真的精确接触力、世界坐标、无误差支撑标签只用于分析和计分，不能悄悄进入声称可实机运行的控制器。
- 外部相机、身体标记可以用于离线计分。若把它们用于闭环控制，必须改写输入条件，明确方法已经增加相对运动观测。
- 若原有信号不能区分关键状态，报告这一信息缺口。允许依据证据提出附加观测；本轮不为维持“只用原传感器”的表述而编造可观测性，也不自动发展一套新视觉系统。

## 4. 计分方法与判定标准

以下“2 个相邻单元、3 次成对比较、60 秒”等是本任务选定的工程筛查标准和工作上限，不是文献结论、统计充分性保证或硬件安全限值。执行前如与实物不适配，应先在任务清单中说明并固定修订；不得在看到成败后放宽标准。

### 4.1 主要终点：实际局部转移

给连续身体单元和接头附近管道做可辨识标记。结合接头出口与目标管包绕区域，预先画定计分区域。必要时使用两个机位；不要求开发自动视觉评分系统。

一次局部转移通过须同时满足：

1. 至少 **2 个相邻且初始尚未进入目标管包绕区域的身体单元**，按身体顺序实际通过接头并进入目标侧包绕；不能仅以头部位移、距离某轴更近、旋转绕了一圈或参考移送量增加计分。
2. 动作包括两段预先规定的移送，中间停止移送指令并通电保持约 3 秒，末端通电保持约 5 秒。保持时保留适用的局部顺应，停止与移送耦合的运动；用于观察运动能否随指令停止及继续。保持时间不计入下面的主动运行时间上限。
3. 期间没有失控摆落、接头外的非预期碰撞、已确认运行限值超限、人工或保护装置承载。实际只是靠整体滑落进入区域的，不能通过。
4. 视频与命令、反馈时间线相互对应，计分无关键遮挡。接触力分配若没有直接观测，只能报告可见包绕和运动稳定性，不推断已经测得前后支撑力。

移送执行阶段最多 **60 秒/次**，其中包括遇阻减速、临时停顿和恢复动作；只有上述预定的中段 3 秒、末段 5 秒保持另计。接入与初态观察预留不超过 10 秒，单次总时长因此不超过 78 秒。预定两段移送应足以要求上述局部目标，但不得突破已确认的速度和角度限制。若在这些条件下连目标都无法合理安排，先修改或否决运动设计，不靠延长运行凑结果。

C0 尽量覆盖与对应移送相近的观察时长，出现失稳立即结束。C0 漂移、中间保持、材料单元迁移共同用于排除明显被动滑落；这些观察仍不能精确分离重力与驱动力的全部贡献，报告中不得据此声称完成了能量或接触力的因果分解。

### 4.2 重复与反馈改善

- **重复的主动转移：**同一个冻结控制版本在至少 2 次可比实机运行中通过上述局部终点。不同版本的成功不能合并；仿真重复不能替代实机重复。
- **反馈初步有效：**最多完成 3 对 `B_cmp/F` 比较。预先选定一个主要改善指标，优先选“是否完成局部终点”；若两者均能完成，可选择与实际问题直接相关的停滞时间或异常滑移幅度，并记录测量误差及有实际意义的最小差值。
- 原则上 F 应在 3 次比较中均满足局部终点，至少 2 对在主要指标上得到超出测量误差的改善，且不引入运行限值或稳定性退化，才记为 `SUPPORTED_PRELIMINARY`。这仍然是小样本初步证据。
- 若 B/F 都顺利完成且主要指标无实质差异，则本轮没有证明新增反馈有收益。不得不断加难度，直到对照失败为止。
- 若试验提前结束、初态不能匹配或观测不足，记录 `INCONCLUSIVE`；如果在可比条件下 F 未改善或更差，记录 `NOT_SUPPORTED`，同时注明检验的具体条件。

不同条件下的实际移送量、异常滑动、保持表现和运行限值均保留，不只给一个“成功”标签。无足够观测时不应强行二选一判成功或失败。

## 5. 按顺序执行的任务

### P0：只整理必需事实，形成一次性任务登记

读取第 8 节的必要资料，核对当前代码与实机状态。交付一页 `run_manifest.md`，至少填写：

- 选定场景与尺寸，20 关节参数，初态和选定的身体标记；已知先验、未知量及模型估计值。
- 控制输入实际可用字段、数据时序和通信方式；可执行的运行限值及其来源。
- C0/B 的计划运动、计分方式、时间上限、停止方式和初态允许误差。
- 仿真与实机阶段的可执行性；缺项由谁提供，当前是否能进入实机。

只读与任务相关的记录，不重做全仓审计、历史试验复现、SHA 校验或全部文献综述。P0 不能给任何实验通过结论。

### P1a：先交付具体运动设计，不启动动力学或实机试验

先完成第 3.1 节，并将以下内容集中写入 `motion_definition.md`，不要为前置设计另建复杂报告体系：

1. **具体怎么动：**给出可计算的曲线、身体材料坐标到曲线位置的映射、移送与滚动关系，以及生成 20 个关节目标的公式或伪代码。用几个关键时刻追踪同一组身体单元，说明后部如何送出、过渡部分如何通过接头、前部如何接入包绕。只有静态曲线或“进度逐渐增加”的文字不算完成。
2. **顺应性放在哪里：**明确基础 B 中持续顺应的输入、作用位置和限幅，以及它如何与移送要求共同形成一组目标角。新增协调反馈 F 此时不开发。
3. **凭什么可能动起来：**指出各阶段预期保留的接触、关节动作如何利用接触推动身体、可能发生的滑移与支撑失效。把尚待实验确认的假设单列；无需在试验前证明全部接触动力学，也不能把这些假设写成保证。
4. **与旧控制器具体差在哪：**只检查相关的旧运动生成代码，列出旧、新在身体移送、过渡段定位、前后运动配合和顺应作用方式上的对应关系及代码位置。旧方案已有曲线和运动变量，不能用“旧方案没曲线、新方案有曲线”解释差异。若实际仅改了准入/释放阈值或变量名称，记录为未形成新候选，不启动后续实验。
5. **20 关节能否表达这个动作：**用必要的离线计算、正运动学或关键姿态图检查身体长度占用、关节范围、连接处、指令连续性和明显穿透。可为此编写最小几何代码，不启动接触动力学试跑。参考动画必须标明人为指定的基座位姿/接触假设；它不证明自由运动的机器人真的会沿该曲线前进。

P1a 结束时写明 `DESIGN_STATUS = READY_FOR_MINIMAL_SIM / NOT_READY` 并指出证据位置。`READY` 只表示已经形成可以检验的具体运动假设，不表示已证明跨管成功或方法具有创新性。

如果缺少完整移送关系、20 关节表达存在明确矛盾，或无法说明相对旧实现的实质变化，交付 `NOT_READY` 和具体缺项后结束。不得跳过设计问题去跑参数扫描，也不得为通过此节点强行声称新旧不同。

### P1b：对已明确的候选做最少仿真

1. 将 P1a 的动作接入最小运行入口，仿真、实机共用控制计算，输入输出适配分开。真实迁移必须由关节指令与接触相互作用产生；不能用虚拟牵引、固定根节点或直接修改世界位姿冒充机器人自主移送。
2. 同一初态各运行一次 C0 和 B。视频中标出身体单元，回答：是否存在实际按序转移？过渡段是否偏离接头？停止移送后发生什么？
3. 若失败，指出一个具体机制，并允许一次有依据的运动构造修订。修订须同步更新 P1a 的运动定义，只重跑受影响的条件。若仍无主动转移证据，且没有可检验的新解释，停止当前候选；不得先堆叠 F 来掩盖运动主干不成立。
4. 仿真通过基本几何、指令与有界执行检查后，尽早进入 P2，不等待全部初态、六场景或完整跨越通过。

若失败只涉及缺乏依据的接触参数，不能凭此证明实机必然失败，也不能把摩擦调到能通过为止。仅在运动与指令本身合理、实机进入条件成立时，提出有限实机诊断；区分“几何/指令错误”与“接触模型不确定”。

### P2：尽早取得实机基础运动证据

按顺序执行 C0 一次、冻结 B 的名义初态重复最多两次。C0 不能保持时不直接继续移送；先结束该初态分支。B 没有任何可辨认的主动材料进展时，不继续进行反馈优劣比较。

每次只回答：

- 哪些身体单元移动，移动发生在何处，是否能保持和继续？
- 失败首先发生在什么位置和时间？该时段指令、关节响应、负载相关信号和视频分别显示什么？
- 同样的指令在仿真里是否预测了相同方向、相近形状和相同失败类型？

若 B 已显示明确主动移送，但被一个具体问题阻断，可以进入 P3；无需先把 B 调到所有条件都通过。若 B 基本动作没有成立，则报告动作问题，不能笼统归咎于“仿真不真实”。

仅在实机证据指向某一主要误差来源时，修正一组相关模型量，例如实际外径/包覆厚度、接触摩擦或执行器响应。区分测量值和估计值；冻结其他组，最多用两次对应仿真检查该修正是否改变结论。不得同时提高摩擦、力矩和阻尼后宣称模型被校准。

### P3：针对一个真实问题设计一种反馈调整

从 P2 或可信实机记录中选一个会阻碍移送的问题，优先选择可在稳定支撑条件下复现的停滞、后部拖滞等。禁止为了制造反馈收益而故意让机器人跌落或过载。

先写一张“观察—信号—调整”表：

| 必填项 | 要求 |
| --- | --- |
| 实际问题 | 指定录像时间段及表现，不直接把角度误差大解释为确定的接触位置或受力方向 |
| 在线信号 | 实际字段、采样率、延迟、滤波和丢失处理；说明为什么可能与该问题有关 |
| 调整动作 | 只选一个主要自由度，如后部送出相位、局部形状或移送速率；给出方向、幅度上限与恢复条件 |
| 反证 | 什么结果会说明信号不足、调整方向错误或收益只来自更保守的固定参数 |
| 公平对照 | B_cmp 的常数安排、选择依据和主要评价指标 |

必要时允许一次轻微、可复现的开发工况，例如来自真实记录的小幅初态偏差；工况大小和允许误差必须明确。优先在 P2 已出现问题的原工况内比较。若另选初态已经改变无移送时的保持或滑动条件，则需在总预算内补做该初态的 C0，可替代第二次名义 B 运行；不能把原初态的漂移量直接外推。此时运动重复性可由后续同一冻结 F 的重复提供。若没有出现需要改进的问题，直接报告“运动已有证据，反馈需求/收益尚未建立”，不随意提高难度。

开发记录不能计入冻结版本验证。F 最多做一次有依据的规则修订；一个调整失败后不在同一轮继续扩展为多套反馈规则。反馈只能无限等待、或信号不能支持所需判断时，作为本轮结论记录。

### P4：冻结后做成对实机比较

冻结控制版本、场景、初态要求、工况、比较指标、滤波和阈值、限值及时间预算。计划最多 3 对运行，顺序采用 `B_cmp→F`、`F→B_cmp`、`B_cmp→F`，降低固定顺序影响。配对间记录供电、温度状态、线缆和接触表面变化；不满足预先允许范围的记录标为不可比并说明原因。

正式比较中不调参。根据反馈表现改变开发规则后，本批不能继续称为同一冻结版本；没有剩余预算就报告未完成。

若两个连续成对结果均无改善且没有新解释，或出现不宜重复的失稳/运行限值问题，提前结束。不得为凑齐三对重复危险失败。必要且仍在预算内时，可做一个未用于开发的仿真初态 B/F 对照，但它只用于检查脆弱性，不能扩大实机泛化结论。

## 6. 总预算、停止条件和分支选择

### 6.1 工作上限

预算是上限，不是必须用完的配额。所有已经开始物理演化或实机动作的尝试均登记，失败、提前中止和无效记录也占次数；不能通过更换文件名、版本号或重新开会话清零。

| 类型 | 计划用途 | 最多次数 |
| --- | --- | ---: |
| 仿真 | 初始 C0/B | 2 |
| 仿真 | 一次运动构造修订后的必要复查 | 2 |
| 仿真 | 实机证据支持的模型修正诊断 | 2 |
| 仿真 | F 开发与一次必要修订；只跑能改变判断的条件 | 2 |
| 仿真 | 冻结后一个额外初态的 B_cmp/F 检查 | 2 |
| 仿真 | 基础设施失效导致的重试余量 | 2 |
| **仿真合计** | **不做参数扫描，不跑整夜批次** | **12** |
| 实机 | C0 保持 | 1 |
| 实机 | B 名义初态重复 | 2 |
| 实机 | 一次开发工况诊断；已有记录够用则省略 | 1 |
| 实机 | 3 对 B_cmp/F 比较 | 6 |
| **实机合计** | **只执行实机进入条件已满足的部分** | **10** |

可以在总额内合理调配尚未使用的次数，但必须先说明仍待回答的问题；不可增加候选步态、反馈问题和场景数量。基本运动最多一次实质修订，F 最多一次实质修订；明显记录错误或接口错误的修复不代表允许无限重试。修复后新启动的动作仍计次。

实机可用时间有限时，优先保留 C0、主动移送重复和有辨别力的对照；省略可选仿真。仿真与实机使用同样的运动时间含义。不得暂停物理时间完成在线预测后，宣称已满足实机实时要求；离线预计算可以，但必须与运行期计算区分。

### 6.2 单次与整轮停止

- 达到已确认的运行限值、通信/观测失效或失稳征兆时，按既有实机停止流程处理。停止移送不等于直接断电；需考虑原有保持与保护流程。
- 在计划持续移送区间内，若身体进展持续低于可辨识精度，执行预先登记的停滞时间窗。建议以 10 秒作为起点，并结合一个完整运动周期和观测精度在开发前固定；不能等待到几百秒再解释为慢慢通过。
- 允许有限的预先定义重整形或退回动作，但必须有持续时间和终点；不得通过反复进入恢复状态规避总时间预算。
- 同类失败重复且新一次不能区分新解释时，停止该分支。预算耗尽、关键观测缺失或硬件不可用时，交付明确的部分结果，不自动续跑。

### 6.3 最终分支

| 得到的证据 | 结论与下一步建议 |
| --- | --- |
| 未形成明确运动关系，或与旧实现无实质区别 | DESIGN_NOT_READY；交付缺项与对照，结束本轮，不启动动力学/实机试验 |
| 同版本重复实机主动转移成立，反馈比较初步支持改善 | 本阶段正面；提出下一轮延长转移范围的建议，不自动执行整身跨越 |
| 主动转移成立，反馈未改善或缺乏必要性 | 部分完成；保留运动主干，报告反馈问题，不为增加算法而加入强化学习 |
| 主动转移成立，但关键状态无法观测 | 部分完成；明确所需相对运动/接触信息，评估最低限度补充观测 |
| 仿真与实机结论不一致 | 列出一致与不一致部分；证据不足时保持未知，不宣布仿真无用或实机一定可行 |
| 有限修订后仍无明确主动转移 | 否决当前候选构造或记录未证实原因，不推广为所有曲线方法/20 关节机器人都不可能 |
| 尚不能运行实机 | 交付实机准备包，状态为 READY_FOR_REAL 或明确缺项；本阶段未通过 |

## 7. 文件安排与最终交付

沿用仓库结构：可运行入口放 `codes/`，公共控制与几何放 `snake_control/`，实验编排与离线评分放 `validation/`，场景生成放 `tools/`。新实现与旧终止方案分开记录；不得覆盖旧轨迹、存档、报告或已有未提交文件。

新实验原始记录放 `experiments/curve_guided_transfer_YYYYMMDD/`，具体日期取实际执行日期。只维护足够复现本轮的材料：

1. `run_manifest.md`：P0 事实、控制输入、运行条件、评价标准和预算。
2. `motion_definition.md`：曲线及移送关系、顺应作用方式、20 关节约束与文献对应。
3. `trial_ledger.csv`：每次编号、阶段、版本、C0/B/B_cmp/F、初态、用时、是否可比、终止原因、主要指标、证据路径。失败和中止不删行。
4. 每次试验的参数、实际命令与反馈时间戳、计分标记、正常速度视频。记录实际源码版本和本轮修改文件的快照即可，不做 SHA 校验，不为每个微调建立庞大归档流程。
5. `result_report.md`：回答下列问题，并给出支持结论的少量关键轨迹/画面；其余原始记录保留链接。

报告必须逐项回答：

- Q1：哪些单元从哪里移送到哪里？哪些证据排除了明显被动滑落？重复结果来自哪个冻结版本？
- Q2：反馈读了什么、实际改变了什么、相对合理对照改善了什么？是否仍可能只是更好的固定参数？
- Q3：仿真在哪些几何/动作/接触现象上与实机一致，哪些不一致？哪些解释尚无法验证？
- 本轮是否只完成局部转移？是否使用人工初态、已知几何、额外传感和非实时计算？
- 共使用多少仿真与实机次数？哪些失败改变了决策？应继续、修改还是停止当前候选，理由是什么？

在报告开头填写，不留模糊的“基本通过”：

```text
DESIGN_STATUS = READY_FOR_MINIMAL_SIM / NOT_READY
ACTIVE_TRANSFER_REAL = PASS / FAIL / INCONCLUSIVE / NOT_RUN
FEEDBACK_BENEFIT = SUPPORTED_PRELIMINARY / NOT_SUPPORTED / INCONCLUSIVE / NOT_RUN
SIM_REAL_SCOPE = 一句话说明已验证的对应关系与主要缺口
OVERALL = DESIGN_NOT_READY / STAGE_POSITIVE / PARTIAL / REJECT_CURRENT_CANDIDATE / READY_FOR_REAL
```

若停在 P1a，只交已完成的任务登记、运动定义和缺项结论，不要求制造实验台账、录像或实机操作包。候选已完成基本验证、但实机尚未执行时，再交 `real_operator_handoff.md`，列明准备状态、实际可运行入口、运行顺序、现有限值、需要采集的信号和终止方式。不能向操作者提供尚不存在或未核对的命令，也不能把计划中的记录写成已经取得的结果。
